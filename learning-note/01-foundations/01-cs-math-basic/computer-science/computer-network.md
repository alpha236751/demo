## 跃点数（Metric）
跃点数（Metric）就是网络接口的“优先级分数”或“路费成本”。

在电脑决定把数据发往哪里时，它会计算每条路线的“总成本”。数值越小，代表成本越低、优先级越高，数据就走这条路。

有线网卡：虽然连接的内网不能上网，但因为它物理速度是千兆，系统给它自动算了个低跃点（比如 10）。

Wi-Fi：因为是无线，速度相对慢，系统给它算了个高跃点（比如 25）。

按键盘 Win + R，输入 ncpa.cpl 并回车，打开网络连接。手动设置跃点数

## HTTP 请求方法

| 方法 | 语义（规范定义） | 幂等性 | 安全性 | 请求体 | 响应体（成功时） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **GET** | 获取资源的**表述**（Representation） | ✅ 是 | ✅ 是 | 禁止携带 | 返回资源数据 |
| **HEAD** | 同 GET，但**只返回响应头**，不返回实体主体 | ✅ 是 | ✅ 是 | 禁止携带 | 无 Body |
| **POST** | 处理资源（**新增**子资源，或提交数据给目标资源处理） | ❌ 否 | ❌ 否 | 携带数据 | 返回新建资源ID或处理结果 |
| **PUT** | 用请求载荷**全量替换**目标资源的所有状态 | ✅ 是 | ❌ 否 | 携带完整资源 | 通常返回更新后的资源或200/204 |
| **DELETE** | 删除目标资源 | ✅ 是 | ❌ 否 | 禁止携带 | 通常返回 204 No Content |
| **OPTIONS** | 获取目标资源支持的**通信选项**（如允许的方法） | ✅ 是 | ✅ 是 | 禁止携带 | 返回 Allow 头（如 `Allow: GET, POST`） |
| **CONNECT** | 建立到目标服务器的**隧道连接**（用于代理） | ❌ 否 | ❌ 否 | 可有可无 | 切换协议至隧道 |
| **TRACE** | 执行**环回测试**，原样返回收到的请求（调试用） | ✅ 是 | ✅ 是 | 禁止携带 | 返回原始请求内容 |


- **安全性（Safe）**：方法不应产生副作用，即**只读**。客户端调用时，不会改变服务器状态。（GET/HEAD/OPTIONS/TRACE）
- **幂等性（Idempotent）**：**多次执行** 与 **单次执行** 效果相同（服务器最终状态一致）。注意：幂等关注的是**状态结果**，不是返回码。

> 当网络超时，客户端可以**安全地重试**所有幂等方法（GET/PUT/DELETE/HEAD/OPTIONS/TRACE），但**绝不能**自动重试 POST/PATCH，否则可能创建多条订单（非幂等）。
