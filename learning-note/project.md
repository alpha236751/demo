## 测评
### RAGAS
RAGAS是专门评测RAG系统的框架。它通常利用大模型作为评审，对问题、检索内容、生成答案和参考答案进行分析。

一条评测数据通常包含：

```python
{
    "question": "Amazon商品被下架后如何申诉？",
    "contexts": [
        "商品下架后，可在卖家后台查看违规原因……",
        "申诉时需要提交商品证明和整改材料……"
    ],
    "answer": "可以先查看下架原因，然后准备证明材料并提交申诉。",
    "ground_truth": "登录卖家后台查看违规原因，准备证明材料后进入申诉入口提交。"
}
```

然后计算：

* Context Precision
* Context Recall
* Faithfulness
* Answer Relevancy

需要注意：RAGAS很多指标依赖 LLM Judge，不是完全确定性的传统公式。因此项目中最好固定：

* 评测模型
* Prompt
* 温度参数
* 测试集
* RAGAS版本

否则多次评测结果可能存在小幅波动。

### 完整的评测流程

你可以这样描述项目中的评测过程：

1. 从真实业务问题中抽取100～300条代表性问题。
2. 由业务人员为每个问题整理参考答案和相关知识文档。
3. 运行RAG系统，保存检索上下文与生成答案。
4. 使用RAGAS计算检索和生成指标。
5. 对低分案例进行人工分析。
6. 优化切分、召回、重排序和Query Rewrite。
7. 使用同一测试集重新评测，对比优化前后的指标。

必须使用同一批测试数据，优化前后的指标才有可比性。

### 指标解释

你简历中写的是：

> 经Query Rewrite、混合检索和重排序优化，Context Precision由0.72提升至0.87，Context Recall由0.76提升至0.90。

面试时可以这样回答：

> 我们先从企业内部常见的平台规则问题中构建测试集，并为每个问题整理参考答案和相关知识文档。系统运行后保存实际召回的上下文和生成答案，再通过RAGAS进行评测。初始版本只使用向量检索，存在关键词匹配不足和无关文档靠前的问题。后来加入Query Rewrite、BM25与BGE-M3混合召回，并使用BGE-Reranker重排序，使Context Precision从0.72提升至0.87，Context Recall从0.76提升至0.90。

但前提是你要继续准备清楚：

* 测试集有多少条？
* 谁制作参考答案？
* Top K设置多少？
* 混合检索如何融合分数？
* 重排序前后分别保留多少条？
* 指标使用什么模型计算？
* 低分样本主要是什么类型？

### 病案 ICD-10 智能编码辅助系统
方案	优点	问题	结论
TF-IDF＋朴素贝叶斯	训练和预测快	对相似诊断区分较弱	作为基础基线
TF-IDF＋逻辑回归	稳定，支持概率输出	多类别边界区分稍弱	作为主要对照
TF-IDF＋LinearSVC	适合高维稀疏文本，相似类别区分较好	不直接输出概率	最终采用
随机森林	容易理解	不适合高维稀疏 TF-IDF 特征	实验后放弃

最终选择字符级 TF-IDF＋LinearSVC，理由可以这样回答：
诊断名称通常比较短，疾病名称、部位和并发症等字符片段具有较强区分性。实验中对比了朴素贝叶斯、逻辑回归和 LinearSVC，LinearSVC 在 Macro-F1 和 Recall@5 上表现更好，而且训练和推理成本低，适合医院内网 CPU 环境，因此最终采用。系统不依赖分类概率，而是根据 decision function 分数生成 Top-5，并使用最高分及前两名分差判断是否转人工。
